# 晒单即入账，打卡即核验 —— TeleAgent 营销群智能中枢

企业微信营销群里的业绩机器人。一线人员照常在群里晒单、拍水印照打卡，机器人自动：

- **晒单即入账**：固定格式的文字晒单 @机器人 发出，当场解析入台账，点赞、判重、按小组 / 战队排名
- **打卡即核验**：「今日水印相机」打卡照，本机 OCR 读水印 → 业务优先 → 视觉模型判有效 / 无效 → 按时段出打卡表
- **定时通报**：业绩通报（文字 + 表格图）、打卡通报（各战队触点 + 未打卡小组），活动期间按点自动发
- **报表与数据**：每天存档晒单 / 打卡 Excel，JSON 数据每日备份，管理员单聊按日期要
- **TeleAgent 接入**：MCP 服务器把台账查询、打卡统计、导出报表开放给 TeleAgent（星辰超级智能体）

> 最早是飞书群关键词机器人，2026-09 迁到企业微信。飞书适配器（`platforms/feishu.py`）还在，但已不维护；
> 下面说的都是企业微信版。

## 一、群里怎么用

**给员工的完整说明**见 [`docs/使用说明.md`](docs/使用说明.md)（可以直接发群）。简要：

| 做什么 | 怎么发 | 机器人回 |
|---|---|---|
| 文字晒单 | 群里 **@机器人** 按模板发 | 点赞；重复的提醒；不记单的说原因 |
| 打卡照 | 群里**不 @** 发一份给大家看，再**单聊机器人**发一份 | 「打卡已记：9.28 14:30 下午｜现场拦截」 |
| 问业绩 | 群里 @机器人 问「今天新盛几单」 | 查台账后回答 |
| 看通报 | 群里 @机器人「通报」/「打卡通报」 | 立刻发一份 |
| 要表格 | **单聊**机器人「晒单表格发我」「打卡表格 9.25」 | 发 Excel（群里要会提示去单聊） |

为什么打卡照要单聊：**手机端企业微信在群里 @ 不了机器人发图片**，而机器人（智能机器人长连接）只收得到 @ 它的群消息和单聊。

### 管理员单聊命令（`config.yaml` 的 `backup.admins`）

| 命令 | 作用 |
|---|---|
| `新活动 秋促专项营销活动 10.1-10.4` | 开新活动（名称可省）。切换前自动备份 |
| `当前活动` / `结束活动` | 看活动状态 / 提前结束（看状态谁都行） |
| 发名册 Excel | 更新名册（只认管理员发的），已记的单按新分组重新归队 |
| `补判打卡` | 把「待判定」的打卡马上再判一遍 |
| `备份` / `备份 9.25` / `json` | 发那天的 JSON 数据备份包 |

**活动期外全部停**：群里晒单、打卡照不记（回一句不在活动期间），定点通报、打卡通报、表情包都不发；
单聊要报表、群里喊「通报」照常。活动存在 `data/activity.json`，删掉它就回到按 `config.yaml` 里星期配置的老办法。

## 二、核心口径

### 晒单记账

- **只认固定格式的文字晒单**（「支局 / 业务类型 / 办理套餐 / 业务号码 / 价值积分 / 是否加载云盒… / 揽收人」模板），
  字段写歪了先规则容错、再让模型抽字段；照片和口语报单只点赞不记
- 归属：**晒单落到发消息人的小组**，揽收人填进清单的揽收人列；发消息的人不在名册才按揽收人归组
- 存量 = 续约，**按前后总和算**：后 > 前 计差价（提值）；后 = 前 积分 0 但算长续约；后 < 前 是降档，不计
- 权益金兑换单标黄待核对；同一单重发按新的覆盖，不重复计
- 细则见 [`docs/套餐资费.md`](docs/套餐资费.md)

### 打卡核验

每张今日水印照片记一次打卡，按水印时间落时段：上午 08:30–11:50、下午 14:00–18:00、晚上 18:00–21:00；
时段之间的空档算下一时段，21:00 以后不统计。判定顺序：

1. **业务优先**：水印「工作内容」写了办成的业务（新增、续约、改档，「策反」算新增）→ 记成该业务，填绿
2. **原样照写**：「异网打卡」「拆机维系」等写进格子（拆机维系成功填绿）
3. **视觉模型**：拦截 / 设备演示（显示为「云盒打卡」）/ 板夹 / 算账 / 异网 / 无效（填红）
4. **本机核对**：异网要在画面里读到其他运营商字样；算账要读到办理界面或算式；
   摊位上一律算拦截；上门入户或进店只聊天没展示东西算无效

- 视觉模型：阿里云百炼 `qwen3-vl-plus`，**额度用完自动换** `qwen3-vl-flash` → `qwen-vl-plus`，并单聊提醒管理员
- 判不了的记「待判定」，涂黑图最多留 3 天，每 10 分钟 + 每次打卡通报前自动补判
- 106 张标注样本评测 93%~95%（评测脚本和样本说明见「七、测试」）

### 通报时刻

| 通报 | 时刻 | 内容 |
|---|---|---|
| 业绩通报 | 11:50、21:00；有新单跟单通报（每小时最多一次） | 文字 + 晒单数据表格图 |
| 打卡通报 | 09:30 10:30 11:50 / 15:00 16:00 17:00 18:00 / 19:30 20:50 | 「上次通报到这次」各战队触点数 + 未打卡小组 + 打卡表图 |

## 三、隐私与安全

- **照片先在本机处理**：OCR 用 RapidOCR 本地跑；送视觉模型前，证件 / 验证码 / 病历 / 长数字所在的行**涂黑**、缩到 1024
- 送文字模型（DeepSeek，判报单、问答）前抹掉手机号、身份证号
- 打卡照不落盘；只有「待判定」的涂黑图临时存 3 天。打卡样本也只存涂黑版，业务单样本不存照片
- `.env`（企微 Secret、模型 key）不进 git、不进备份
- 名册、台账、打卡记录等数据都在服务器 `data/` 下，不进 git（见 `.gitignore`）
- Excel 报表不发群，只单聊发；JSON 备份只发管理员

## 四、部署与运维

生产环境：一台 Linux 服务器（地址见 `deploy/push.sh`），原生 venv + systemd 服务 `feishu-bot`（`Restart=always`）。

```
/opt/feishu-bot/         代码（push.sh 推上来的，不要在服务器上直接改）
/opt/feishu-bot/data/    配置和数据（BOT_DATA_DIR）：config.yaml .env roster.json campaign.json checkin.json
                         activity.json userid_map.json 各种状态文件 / archive/ backups/ history/ samples/
/opt/feishu-bot.git      代码仓库（push.sh 顺带同步），外部另有 GitHub 私有仓库
```

### 改代码

```bash
git add -A && git commit -m "改了什么、为什么"
bash deploy/push.sh              # 推已提交的版本 + 重启 + 看启动日志
bash deploy/push.sh --no-restart # 只推
bash deploy/push.sh --rev 51d390b  # 退回某个旧版本
```

- 有没提交的修改 `push.sh` 会拒推；服务器 `/opt/feishu-bot/VERSION` 记着在跑哪一版，启动日志也打「代码版本」
- **本机不要启动 `bot.py`**：同一个 BotID 两边连会抢消息

### 改配置

- 直接改服务器 `data/config.yaml`，5 秒内热加载，不用重启（仓库里的 `config.yaml` 是模板）
- 改 `data/.env` 要 `systemctl restart feishu-bot`
- 常用命令、恢复备份、换 key 等操作步骤见 [`常用命令.txt`](常用命令.txt)

### 自动任务与保护

| 项 | 说明 |
|---|---|
| 断线看门狗 | 长连接断开超 3 分钟自动重启进程；断线 ≥5 分钟，恢复后在群里提醒重发 |
| 02:30 数据备份 | `data/backups/备份_日期.zip`（JSON + config.yaml），留 14 天 |
| 02:35 报表存档 | `data/archive/晒单/`、`data/archive/打卡/` 存前一天 Excel，留 14 天 |
| 写之前留底 | 台账 / 打卡 / 名册 / 活动每次保存前留旧版本到 `data/history/`，各留 20 版 |
| 日志 | journald 最多 600M / 30 天（`deploy/journald-limit.conf`），cron 日志每周轮转 |

### `.env`

| 键 | 说明 |
|---|---|
| `WECOM_BOT_ID` / `WECOM_BOT_SECRET` | 企微智能机器人长连接凭证（必填） |
| `WECOM_CHAT_IDS` | 定点通报发到的群 ID，逗号分隔 |
| `LLM_API_KEY` | 文字模型（DeepSeek）：判报单、问答助手、晒单容错 |
| `VISION_API_KEY` | 视觉模型（阿里云百炼）：打卡照判定 |
| `WECOM_WATCHDOG_SECONDS` | 看门狗秒数，默认 180 |
| `OCR_WORKERS` | OCR 并发，小内存机器设 1 |

## 五、TeleAgent 接入

`mcp_server.py` 是 MCP 服务器（11 个工具：查台账、排名、打卡统计、导出报表、导入名册等）。
TeleAgent 桌面版导入 `teleagent/mcp_config.json`，启动本机的 `mcp_remote.py`，它经 SSH 在服务器上起 `mcp_server.py`，
服务器不开端口。详见 [`docs/TeleAgent接入.md`](docs/TeleAgent接入.md)。

⚠️ 这套配置用的是服务器 root 密钥，只给管理员本人用，不要发给别人。同事看业绩在群里 @记单机器人即可。

## 七、测试（都不联网、不花钱）

```bash
python test_rules.py          # 一句话会走规则、模型还是丢弃
python test_parse.py          # 晒单解析：严格解析 / 容错抽字段
python test_bulletin.py       # 离线生成一份通报（文字 + PNG + Excel）
python deploy/preflight.py    # 上线自检：凭证、配置、模型、目录（在服务器上带 BOT_DATA_DIR 跑）
```

**打卡判定评测**：标注样本（涂黑版）在服务器 `data/samples/checkin/`，`index.jsonl` 记标注和脱敏文字。
改提示词或换模型后，把样本临时拉到本机，用评测脚本全量重跑（会调视觉模型、用额度），跑完删掉本机副本。
**提示词一改其他样本会漂，每次都要全量重跑。**

## 八、排查

| 现象 | 先看 |
|---|---|
| 群里 @ 了没反应 | `journalctl -u feishu-bot -n 50`：有没有「收到消息」；没有就是没送到（机器人不在群、没 @ 到） |
| 机器人整体没反应 | `systemctl status feishu-bot`；日志里有没有「长连接已就绪」；看门狗会在断线 3 分钟后自动重启 |
| 晒单没入清单 | 日志里「不是固定格式的晒单」→ 模板字段不对；「活动期外」→ 先发「新活动」 |
| 打卡一直「待判定」 | 管理员有没有收到额度 / key 提醒；换 key 后重启，自动补判 |
| 打卡归到「未识别」 | 发送人账号 ID 对不上名册姓名 → 在 `data/userid_map.json` 加 `{"账号ID": "姓名"}` |
| 通报没发 | 是不是活动期外；日志里「打卡通报定点」「通报」有没有发送失败 |
| `config.yaml` 改了没生效 | 日志里「config.yaml 解析失败」→ YAML 写错了，还在用旧配置 |
