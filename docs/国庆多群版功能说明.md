## 一、三个群分别收什么

| 群 | 谁在这里 @机器人 晒单 | 机器人往这里发 |
|---|---|---|
| 城区支局营销活动群 | 城区活动人员 | 点赞、战报；**城区活动晒单通报、城区活动打卡通报**；定时表情包 |
| 农村支局营销活动群 | 农村活动人员 | 点赞、战报；**农村活动晒单通报、农村活动打卡通报**；定时表情包 |
| 綦江分公司秋促营销攻坚群 | 所有人都可以（主要是没参加活动的人） | 点赞；**支局总表**；**支局长打卡点检表** |

打卡照所有人都是**单聊**发给机器人，不在群里发给机器人。

- ✅ 例：10.2 上午 10:30，城区群收到城区晒单通报 + 城区打卡通报；农村群收到农村的两份；攻坚群收到支局总表 + 支局长到场（上午）
- ❌ 反例：城区群里不会出现农村的任何数据，也不会出现「恭喜赶水支局」
- ❌ 反例：攻坚群不发表情包、不播战报

## 二、名册和「这个人是谁」

### 2.1 四张名册

管理员单聊机器人：先发一句是哪张名册，2 分钟内再发 Excel。

| 命令 | 名册 |
|---|---|
| `城区支局名册` + Excel | 城区所有支局的人 |
| `城区活动名册` + Excel | 参加城区活动的人（现在 64 人那张就是这张） |
| `农村支局名册` + Excel | 农村所有支局的人 |
| `农村活动名册` + Excel | 参加农村活动的人 |

- 每张的列【待给】：到时候和你一起定（活动名册应该还是 姓名 / 分组 / 战区）
- ✅ 例：发「农村活动名册」再发 Excel → 回「农村活动名册已更新：58 人 / 12 个战队 / 30 个小组」
- ❌ 反例：不是管理员发 → 回「名册只能管理员更新」
- ❌ 反例：没先说是哪张就直接发 Excel → 回「请先说是哪张名册：城区支局 / 城区活动 / 农村支局 / 农村活动」
- 名册更新后，之前记的单和打卡按新名册**自动重新归类**

### 2.2 每个人归成哪一类

企微账号 → 名册里的姓名（账号是姓名拼音的自动对上，对不上的管理员补 `userid_map`）→ 类别：

| 类别 | 条件 |
|---|---|
| 城区活动人员 | 在城区活动名册 |
| 农村活动人员 | 在农村活动名册 |
| 城区非活动人员 | 在城区支局名册，不在活动名册 |
| 农村非活动人员 | 在农村支局名册，不在活动名册 |
| 认不出 | 账号对不上任何名册 |

- ✅ 例：账号 `YangTong` → 杨桐 → 在城区活动名册 → 城区活动人员
- ✅ 例：账号 `LiSi` → 李四 → 只在农村支局名册 → 农村非活动人员
- ❌ 反例：账号 `echo.` 对不上任何人 → 认不出（晒单、打卡各有处理，见三、七）

## 三、晒单（群里 @机器人）

### 3.1 按人记，一单只记一次

在任何一个群 @机器人 晒单 → 认人 → 在台账里记**一条**（带上类别、小组、晒单里写的支局）→ 各张表按类别取：

| 谁 | 在哪个群晒 | 城区活动表 | 农村活动表 | 支局总表 |
|---|---|---|---|---|
| 城区活动人员 | 城区群 / 攻坚群 | ✅ | | ✅ |
| 农村活动人员 | 农村群 / 攻坚群 | | ✅ | ✅ |
| 非活动人员 | 攻坚群 | | | ✅ |
| 非活动人员 | 活动群 | ❌ | ❌ | ✅ |
| 认不出【我的假设】 | 任何群 | ❌ | ❌ | ✅ 按晒单里写的支局记，标黄；单聊提醒管理员补名册 |

- ✅ 例：农村活动人员小王在**攻坚群**晒了新增 199 → 农村活动表、支局总表都有这单
- ❌ 反例：城区非活动人员在**城区群**晒单 → 点赞照常，但城区活动通报里没有这单，只进总表
- ❌ 反例：同一单（同一业务号码）在城区群、攻坚群各发一次 → 只算一次，后发的覆盖先发的，回「已按最新一条更新」
- ❌ 反例：单聊发文字晒单 → 不记，回「晒单请在群里@我发，单聊发的不记单」（和现在一样）

### 3.2 总表里这一单算给哪个支局

- 算给**晒单里「支局」一栏写的支局**（落地支局）【我的假设】；没写支局的，算给发单人在名册里的支局
- 跨区域按 6:4 拆：**暂时不做**【待领导】
- ✅ 例：通惠的人晒单写「支局：古南支局」→ 总表里算古南
- ❌ 反例（暂不做）：揽收人是通惠的、落地古南 → 不拆 6:4，全算古南

### 3.3 回复和战报

- 点赞：在发单的那个群回
- 战报（「恭喜 XX 支局……」）：**只在活动群发，只数本区的单**；攻坚群里的单只点赞、不播战报
- ✅ 例：农村活动人员在农村群晒单 → 农村群点赞 + 农村战报
- ❌ 反例：农村活动人员在攻坚群晒单 → 攻坚群只点赞；农村群也不补播战报【我的假设】（单照样算进农村活动表和通报）

## 五、攻坚群支局总表

### 5.1 样子（按你给的模板）

标题「10.1-10.7国庆节营销活动通报」；列：分类 | 支局 | **当日**（新增宽带 / 中高套 / 千兆500兆 / 套包 / 单号卡 各「目标 / 完成值 / 进度」+ 综合完成进度）| **累计**（同左）| 同类排名 | PK激励；最后一行合计，下面一行宽带折算注释。

17 个支局：一类 通惠 古南 文龙 万盛 东林；二类 打通 赶水 东溪 青年 新盛 郭扶；三类 三江 南桐 安稳 永新 隆盛 三角。

每半小时发一张表格图到攻坚群；表头注明「按晒单统计，最终以竣工为准」【我的假设】。

### 5.2 怎么算【待领导：综合完成进度的算法你说有问题，今天核对】

我现在的理解：
1. 每单按第六节算出五项各多少，算给落地支局（见 3.2）
2. 每项进度 = 完成值 ÷ 目标；千五、套包、单号卡最多算 130%，宽带、中高套不封顶
3. 综合完成进度 = 宽带进度×25% + 中高套×30% + 千五×20% + 套包×15% + 单号卡×10%
4. 当日 = 今天的单，目标【待领导：每日目标还是总目标÷7】；累计 = 10.1 起到现在
5. 同类排名：按**累计**综合进度，一类、二类、三类各自排
6. PK激励按当前名次：一类 +2000 / +1500 / 0 / −1500 / −2000；二类 ±1500 / ±1200 / ±1000；三类 ±1200 / ±800 / ±500；
   综合进度超过 100% 还排在输的一边，写「−1500（分公司出资）」
7. 合计行：目标、完成值各自加总，进度用加总的数算

- ✅ 例（目标是编的）：通惠累计 宽带 12/20=60%、中高套 18.3/15=122%、千五 30/20=150%→按130%、套包 25.5/30=85%、号卡 16/10=160%→按130%
  → 综合 = 15 + 36.6 + 26 + 12.75 + 13 = **103.35%**；一类第 2 → PK激励 **+1500**
- ❌ 反例：9.30、10.8 晒的单不算
- 【待领导】新盛：人在城区群、PK 算二类？

### 6.2 各项规则

**新增宽带**：新增融合、单宽、副宽各 1 条；780 包年、明厨亮灶 3 条算 1；390 包年、酒店、短期、40 元及以下列收 5 条算 1；明星机赠送不算；存量不算。
晒单里要写出「明厨亮灶 / 酒店 / 短期 / 列收 / 明星机 / 780 包年 / 390 包年」这些字，机器人才折算；没写就按 1 条算。

**新增中高套**：只算新增融合宽带；139–199 记 1，239 及以上记 1.3；单宽、号卡、存量都不算。

**千兆 / 500兆**：**每条宽带**满足下面任一条记 1（一条宽带只记一次）：
① 新增 500M 以上（139 及以上融合、138 / 198 单宽、1390 / 1990 包年、副宽 60）　② 存量迁转后**宽带套餐本身** ≥239（按 2000M 系数；**只看宽带价格，不加套包**：199+云盒+FTTR 不算 2000M）
③ 存量迁转到 139 及以上且提值 ≥10　④ 存量加包：附加 ≥10 且加完总价 ≥139　⑤ 看家守护 / FTTR 等**付费**小合约、FTTR-H / FTTR-B
**2000M 系数**（存量，续约后宽带套餐是 239 / 299 / 399 —— 是不是 2000M 只看宽带价格；高迁 / 平签 / 低签再按前后**总和**比）：高迁 1.5 / 平签 1.2 / 低签 1.1。低签照旧不计积分、长续约。新增 2000M 记 1。
79、99 新增和 38 副宽（300M）不算；权益金兑换的 FTTR 不算。

**套包**（一单算一次）：一单付费套包月费合计 V；套包分 = 1 + (V − 9.9) ÷ 10（V ≤ 9.9 就是 1）；每台智屏再加「月费 × 0.3」。
权益金兑换的 FTTR、云盒不算进 V【待领导：哪些是权益兑换、晒单怎么写才分得清】。副卡、1 元提速不是套包。

**单号卡**：19 元及以上的号卡（山城卡、单C、携转、异网卡、橙分期）各 1；副卡不算；直管不算【待领导：直管指什么】。

**小区 / 场镇 ×1.1**：名单里标出做小区 / 场镇营销的人，他们发展的新增宽带、中高套 ×1.1（活动群里还有价值积分 ×1.1）。
- ✅ 例：小区营销人员 新增 199 → 宽带 1.1、中高套 1.1
- ❌ 反例：同样一单，不是小区营销人员 → 宽带 1、中高套 1

### 7.2 认人三步

1. 按**发照片的人的账号**查名册 → 他的小组
2. 查不到 → 按照片水印里「小组成员」的姓名在名册里找
3. 还找不到 → 不记

### 7.3 机器人回什么

| 情况 | 回复 |
|---|---|
| 记上了 | 「打卡已记：10.2 14:40 下午｜现场拦截」（一次几张就几行） |
| 类型一时判不出 | 「打卡已记：10.2 14:40 下午｜类型稍后判定」（自动补判） |
| 认不出人（三步都不行） | 「**无法查询到您的账号姓名信息，请修改账号信息或打卡照人员信息后重新发送**」 |
| 非活动人员 | 「**你不在活动名单里，请核实自己账号信息并重新发送**」 |
| 同一张发过了 | 「这张之前已经记过了（10.2 14:40）」 |
| 不是今日水印照片 | 「这张不是今日水印照片，没有记打卡」 |
| 水印看不清时间 | 「水印上没认出拍摄时间，没有记打卡，换张清楚的再发」 |
| 21:00 以后拍的 | 「打卡已记：10.2 21:10 21:00 以后，不计入统计｜…」 |
| 活动期外 | 「现在不在活动期间，打卡没有记录」 |

- ✅ 例：杨桐（城区活动）发一张 → 记到他的小组，城区打卡表多一格
- ✅ 例：账号 `echo.` 认不出，但水印「小组成员：谭启伦，赵兴禄」是城区 5 组的 → 记到城区 5 组
- ❌ 反例：账号认不出、水印里的名字也不在名册 → 不记，回「无法查询到您的账号姓名信息……」；他改好账号名再发同一张 → **重新检查**（因为上次没记，不算重复）
- ❌ 反例：城区非活动人员发一张 → 不记，回「你不在活动名单里……」；但照片**还是**拿去做支局长人脸核验（见第八节）

### 7.4 判定和通报（不变）

- 判定规则和现在一样：工作内容写了业务 → 记业务填绿；否则视觉模型判拦截 / 云盒打卡 / 板夹 / 算账 / 异网 / 无效；判不了的「待判定」自动补判
- 时段：上午 08:30–11:50、下午 14:00–18:00、晚上 18:00–21:00；空档算下一段，21:00 后不统计
- 打卡通报：城区群发城区的、农村群发农村的，每半小时一次：「XX–XX 时段，各支局触点情况：X战队 N 户（未打卡 K 组）……请各位支局长关注未打卡小组！！！」+ 打卡表图
- 集合照不算打卡类型，人工处理

## 八、支局长打卡点检表（人脸识别，只发攻坚群）

按用户 09-29 给的「9.28日支局长打卡情况点检」图做成表格图，每半小时发到攻坚群；**不统计打卡类型，只记打卡时间**。

### 8.1 表的样子

标题「10.2日支局长打卡情况点检（7:30-现在时刻）」；列：类别 | 支局 | 支局长 | 早会 | 中午集合 | 第1户 … 第9户（不够就往后加列）；
一个支局可以有 1–2 个支局长（按支局长名单，【待给】）；格子里写时间（如 8:20、14:02、10:58）。

### 8.2 怎么认

- 从 **07:30** 起，**每一张**单聊打卡照（不管谁发的、这张打卡记没记上）都和支局长的人脸比对，认出谁就记「谁、几点（水印时间）、这张照片几个人、工作内容」
- **早会**：一类（城区）集合约 8:20，二、三类（农村）约 8:00。【我的设计】早会窗口 07:30–09:00，这段里第一张认出他、而且是**集合照**的时间填进「早会」
- **中午集合**：约 14:00。【我的设计】窗口 13:30–14:30，这段里第一张认出他的**集合照**填进「中午集合」

- **当日目标**：没配 `guoqing.daily_targets` 就用累计目标 ÷ 活动天数【待领导】
- **总表**：没配目标的格子写「-」、文字里说「目标还没配」；支局认不出的单在文字里列出；数字放不下自动缩字
- **支局长点检表**：当天的「未打卡」要等窗口过了才写（早会 09:00 后、中午 14:30 后），名字标红当天 18:00 后才判；
  `休息 杨钰航 [10.2]`、`补记 [支局] 严健齐 [10.2] 10:37` 只给管理员单聊
- **人脸比对单独一条队列**（用户 09-29 提议）：打卡读完水印就把照片交过去，不等比对完就继续判类型、发回执，两边同时跑；
  出点检表前等比对做完
- **照片不漏**：一条消息几张图每张都下，失败重试一次，还失败回执里写「第N张：照片没下载下来，请重发这一张」；
  多张时回执每行加「第N张：」。正常重启（发布、手动）时还没回执的单聊照片，挨个回「机器人正在重启，这条的照片还没处理，请 1 分钟后重新发一次」
  （以前会悄悄扔掉）。7 条消息 9 张同时进来的压测：10 秒全部回执、一张不漏
- **活动文件缓存**：两条「新活动」挨着发时偶尔还用旧活动（测试 1/6 复现），已修；**线上版本也有这个问题，还没修**
- 上线步骤见 `docs/国庆版上线清单.md`
- **无效打卡兜底**（用户 09-29 定）：单聊打卡判成无效、或者一时判不出来（待判定，当无效算），回执后面加
  「请在 10 分钟内（14:50 前）重新拍一张发来，有效的会替换这条」（10 分钟从机器人回复时算）；
  同一个人 10 分钟内发来有效的 → 替换他最近那条无效，**用旧的时间和时段**，回「打卡已记：10.2 14:40 下午｜现场拦截（已替换 14:40 那条无效打卡）」；
  超过 10 分钟照常另记，原来那条无效保留；10 分钟内再发还是无效 → 不特殊处理，照常另记（它自己也有 10 分钟）；
  别人的有效照片不替换你的无效；替换掉的待判定不再补判。窗口只在内存里，机器人重启就没了
